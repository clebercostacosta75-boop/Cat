NOME DO PROJETO
Sistema de Gestão de Cursos e Certificações - CAT Cursos

DESCRIÇÃO
Plataforma completa para gestão de cursos presenciais, híbridos e online, com 
certificação digital, controle financeiro, gestão de instrutores, empresas 
clientes, alunos, e integração com múltiplos canais de comunicação (WhatsApp, 
Email, SMS).

OBJETIVO PRINCIPAL
Centralizar todas as operações de treinamento corporativo com automação de 
workflows, certificação digital com assinatura eletrônica, e relatórios 
financeiros completos.

TIPO DE APLICAÇÃO
- Frontend: React + Vite
- Backend: Deno (Base44 Functions)
- Database: PostgreSQL (Base44 Entities)
- Autenticação: Base44 Auth
- Tipo de Deploy: Web (SPA) + Mobile (React Native)

PÚBLICOS PRINCIPAIS
1. Gestor Master (Acesso Total)
2. Editores (Gerenciam Dados)
3. Clientes/Empresas (Visualização)
4. Alunos (Portal Self-Service)
5. Instrutores (Dashboard Operacional)

SEÇÃO 6: PRECIFICAÇÃO E FATURAMENTO
================================================================================

MODELOS DE PRECIFICAÇÃO:

1. Por Aluno (Per Student)
   - Valor unitário por aluno
   - Total = unit_price × number_of_students
   - Exemplo: R$ 500/aluno × 20 alunos = R$ 10.000

2. Por Turma Fechada (Per Closed Class)
   - Valor fixo por turma, independente de quantidade
   - Total = fixed_class_value
   - Exemplo: R$ 8.000 por turma (mín. 10 alunos)

CÁLCULO DE RECEITA:

empresa.company_courses[]:
  ├─ course_id, course_name, workload_hours
  ├─ billing_type (per_student ou per_closed_class)
  ├─ specific_price (ou class_fixed_value)
  ├─ included_students_limit (default 15)
  └─ Para per_student: total = specific_price × students
     Para per_closed_class: total = class_fixed_value

ClassSchedule:
  ├─ unit_value (price por aluno ou turma)
  ├─ students_count
  └─ total_value = unit_value × students_count (ou fixed)

SERVIÇOS ADICIONAIS:

empresa.additional_services:
  ├─ coffee_break_morning: valor_unitário × students
  ├─ coffee_break_afternoon: valor_unitário × students
  ├─ lunch: valor_unitário × students

ClassDailyRecord:
  ├─ lunch_cost, transport_cost, coffee_break_cost, taxi_cost
  └─ total_daily_cost = soma de todos

FATURAMENTO MENSAL (BMM):

BMMRecord:
  ├─ period: "Janeiro/2025"
  ├─ total_value: soma de todas as turmas do período
  ├─ total_classes: número de turmas
  ├─ total_students: número de alunos atendidos
  └─ status: Rascunho → Pendente → Aprovado → Gerado → Enviado

SEÇÃO 7: SISTEMA DE CERTIFICADOS
================================================================================

CICLO DE VIDA DO CERTIFICADO:

Status: pending_signature
└─ Recém gerado, aguardando assinatura do aluno
└─ Link válido por 7 dias
└─ Reenvio automático em 48h se não assinado

Status: signed
└─ Aluno assinou digitalmente
└─ Pronto para download

Status: active
└─ Certificado em vigor
└─ Dentro do período de validade
└─ Pode ser baixado pelo aluno/empresa

Status: expired
└─ Prazo de validade expirado
└─ Bloqueado automaticamente após vencimento
└─ Download pode ser bloqueado conforme política

Status: revoked
└─ Certificado revogado manualmente
└─ Motivo registrado em revocation_reason
└─ Data e responsável em revoked_at/revoked_by

PRAZO PARA DOWNLOAD:

recipient_type: aluno
└─ Prazo padrão: 30 dias após emissão
└─ Definível via download_deadline
└─ is_blocked: true após deadline ou vencimento

recipient_type: empresa
└─ Prazo padrão: 45 dias após emissão
└─ Maior prazo para empresa ter acesso

DADOS DO CERTIFICADO:

Front:
  ├─ title: "CERTIFICADO"
  ├─ subtitle: "CAPACITAÇÃO PROFISSIONAL"
  ├─ student_name (destaque com formatação especial)
  ├─ course_name, duration, dates
  ├─ location_and_date
  └─ signature_url (assinatura digital)

Back:
  ├─ registration (número interno de registro)
  ├─ programmatic_content[] (módulos e horas)
  ├─ technical_responsibles[] (instrutor, CREA, etc)
  └─ verification_code (para validação online)

VALIDAÇÃO ONLINE:

CertificateValidate (página pública):
  └─ Usuário insere certificate_code
  └─ Sistema busca Certificate e valida
  └─ Mostra status, datas, responsáveis
  └─ QR Code aponta para esta página

SEÇÃO 9: 12 PROBLEMAS CONHECIDOS
================================================================================

1. ⚠️  Sincronização de Permissões (MEDIUM)
   Descrição: Usuário pode ter delay ao mudar de página se permissões 
              forem alteradas pelo admin enquanto está logado
   Status: Controlado com cache de 5 min
   Solução: Refrescar página manualmente ou aguardar refresh automático

2. ⚠️  Recursão em AuditLog (MEDIUM)
   Descrição: Ações de auditoria podem gerar recursão se mal configuradas
   Status: Validado em deploy
   Solução: Não registrar logs de logs

3. ⚠️  Exceções em Polling de Permissões (MEDIUM)
   Descrição: Polling pode gerar exceções se usuário sair do sistema
   Status: Try-catch implementado
   Solução: Limpar intervalos na desmontagem de componente

4. ⚠️  Cálculo de Excedente em Turma (LOW)
   Descrição: Cálculo de excedente de alunos (acima de included_limit)
              pode ter imprecisões em turmas mistas
   Status: Requer revisão de regra de negócio
   Solução: Documentar regra exata e testar casos extremos

5. ⚠️  Integração SAP (UNITAPAJÓS) (HIGH)
   Descrição: Integração SAP com mapeamento de códigos pode falhar
              se código não existir no SAP
   Status: Validação de existência não implementada

const PermissionsProvider = ({ children }) => {
  const [role, setRole] = useState(null);
  const [allowedKeys, setAllowedKeys] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const fetchPermissions = async () => {
      try {
        const user = await base44.auth.me();
        if (!user) {
          setLoading(false);
          return;
        }

        setRole(user.role);

        // RBAC mapping
        const permissionMap = {
          'admin': null, // acesso total
          'gestor_master': GESTOR_MASTER_PERMISSIONS,
          'editor': EDITOR_PERMISSIONS,
          'cliente': CLIENTE_PERMISSIONS
        };

        const permissions = permissionMap[user.role];
        setAllowedKeys(permissions);
      } catch (error) {
        console.error('Erro ao buscar permissões:', error);
      } finally {
        setLoading(false);
      }
    };

    fetchPermissions();

    // Polling de 5 em 5 minutos
    const interval = setInterval(fetchPermissions, 5 * 60 * 1000);
    return () => clearInterval(interval);
  }, []);

  return (
    <PermissionsContext.Provider value={{ role, allowedKeys, loading }}>
      {children}
    </PermissionsContext.Provider>
  );
};


AUTHCONTEXT.JSX (Autenticação)

const AuthProvider = ({ children }) => {
  const [user, setUser] = useState(null);
  const [isAuthenticated, setIsAuthenticated] = useState(false);
  const [isLoadingAuth, setIsLoadingAuth] = useState(true);
  const [authError, setAuthError] = useState(null);

  useEffect(() => {
    const checkAuth = async () => {
      try {
        const isAuth = await base44.auth.isAuthenticated();
        setIsAuthenticated(isAuth);

        if (isAuth) {
          const me = await base44.auth.me();
          setUser(me);
        }
      } catch (error) {
        setAuthError({
          type: 'auth_error',
          message: error.message
        });
      } finally {
        setIsLoadingAuth(false);
      }
    };

    checkAuth();
  }, []);

  const navigateToLogin = () => {
    base44.auth.redirectToLogin();
  };

  return (
    <AuthContext.Provider value={{
      user,
      isAuthenticated,
      isLoadingAuth,
      authError,
      navigateToLogin
    }}>
      {children}
    </AuthContext.Provider>
  );
};
